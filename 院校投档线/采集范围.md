## 三、口径说明

1. 这里的省份是**考生省份**（`local_province_id`），即「某省考生报考某校」的划分维度，**不是行政区划全集**。
2. 采集器内部的 34 个 `province_id`（**院校所在省**）完备切分是**零丢失校验手段**（见 [`数据说明.md`](数据说明.md) 第三节），不是本目录的文件划分维度。文件按 `local_province_id` × `year` 命名，**文件数 = 有效省份数 × 6 = 186**。
3. 年份 2021–2026 是源站当前可查询区间，2026 为最新年份。
4. **2026 年数据明显偏少**（如西藏 17 条 vs 2025 年 464 条，青海 396 条 vs 2586 条），说明源站仍在补录。这正是必须写明基准日的原因；后续复采时这些数字预计会增长。

## 四、起止边界

| 边界项 | 值 |
| --- | --- |
| **采集基准日（快照时间）** | **2026-11-08 ～ 2026-11-09**（初版 168 个单元为 11-08，补采 18 个单元为 11-09；各单元精确时间见 `采集统计.csv` 的 `采集时间` 列） |
| 省份范围 | 31 个有效省份（全量） |
| 年份下限 / 上限 | 2021 / 2026 |
| 版本 | 采集器 v5，四道闸门全通过 |
| 数据性质 | **静态快照**，非实时同步 |

本仓库只保证「截至上述基准日，源站对 31 省 × 2021–2026 年所返回的数据」被完整采下。此后源站的任何补录、修订或新增年份，都不会自动出现在这里。

## 五、复采 / 增量约定

以采集单元 `(省, 年)` 为最小更新粒度：

1. **判定变化**：重跑 v5 采集器，比较新的 `num_found`（34 省分片 Σ 守恒基准）与 [`_manifest.json`](_manifest.json) 记录值；条数或 `sha256` 任一变化即视为源站有更新。
2. **达标才覆盖**：只有四道闸门全通过、`pages_failed = 0`、`count = num_found = len(items)` 的新结果才允许覆盖；未达标则**保留旧文件**并记录异常，绝不写入半成品。
3. **清单补齐**：本次已按 `cutoff_54_*.json` / `cutoff_63_*.json` / `cutoff_64_*.json` 补入 18 份；后续若再发现缺口，同样按组合补采并刷新 `采集统计.csv` 与本文件状态。
4. **新增维度**：源站若新增年份或省份，按同名规则新增文件并更新范围表。
5. **留痕**：每次复采更新 `_manifest.json`（字节数、sha256、采集时间、闸门结果），便于比对两次快照差异。

> 复采触发建议：每年高考录取结束后（新年份发布）、发现源站修订历史数据时、或发现清单缺口时；不必整库重采。

## 六、同步机制

本仓库（GitHub `EdisonFan/gk-collect`）是**唯一真源**，CNB `cooledi/gk-collect`（私有）为逐 ref 一致的完整镜像，由 [`.github/workflows/sync-to-cnb.yml`](../.github/workflows/sync-to-cnb.yml)（GitHub Actions）推送：`main` + 全部 `cutoff-*` 分支，`--force --prune`。CNB 侧**只读**，不单独维护内容。

- **状态**：已启用。GitHub 仓库 Settings 的 `CNB_TOKEN` 已配置；同名仓库 `cooledi/gk-collect` 已建为私有仓。
- **触发方式**：`workflow_run`（采集流水线 `gk-cutoff` 每次 run 完成后）、`on.push(main)`（归档/代码更新）、`workflow_dispatch`（手动补同步）。**不用 `on.push: cutoff-*`**：采集器用默认 `GITHUB_TOKEN` 推分支，GitHub 规定该 token 产生的 push 不会再触发 workflow（防递归），实测无效。
- **镜像范围**：`main`（含本 `院校投档线/` 归档目录与采集器代码）+ 全部 `cutoff-*` 结果分支；`--prune` 会自动清理 CNB 上源站已删除的分支。
- 归档按接口组织：一个接口一个中文文件夹。新增接口只需在 GitHub `main` 上加目录 + 一组新分支，CNB 自动跟上。
