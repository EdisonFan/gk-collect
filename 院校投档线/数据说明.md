# 院校投档线 · 数据说明

## 一、是什么数据

「院校投档线」记录**某高校在某考生省份、某录取年份、某批次/科类（或新高考专业组）下的投档最低分、最低位次，以及与批次线的分差**等。

一条记录 = 一所院校 × 一个招生单元。它是志愿填报中判断「某校在某省某年录取门槛」的基础数据，**不包含考生个人信息，也不包含具体专业的录取分数**（专业录取分属另一个接口）。

## 二、来源接口

| 项 | 值 |
| --- | --- |
| 接口 uri | `apidata/api/gk/score/province` |
| 完整调用 | `GET https://api.eol.cn/web/api/?uri=apidata/api/gk/score/province&local_province_id=<省>&year=<年>&page=<页>&size=<每页>` |
| 查询维度 | `local_province_id`（**考生省份**）× `year`（年份）；`local_province_id` 有效取值 **31 个**（大陆 31 个省级行政区，实测 71 台湾 / 81 香港 / 82 澳门 `numFound=0`） |
| 响应特点 | 该 uri 在前端 `apiConfig.eneryptionList` 中被标记为加密接口，直接请求只会得到空 `data` + 非空 `encrydata`；归档中的 `items` 是采集器解出的明文 `data.item[]` |
| 采集器 | `collect_cutoff.py`，版本 **v5** |
| 执行环境 | GitHub Actions（`EdisonFan/gk-collect`），每个采集单元一个 `cutoff-<省>-<年>` 分支 |

> 接口有一个关键坑：无筛选条件查询时 `numFound` 会被截断在 **10000**，是假总数。v5 采集器因此改用 34 个 `province_id` 分片之和作为守恒基准真值。

## 三、采集单元与零丢失校验

一个**采集单元** = 一个 `(local_province_id, year)` 组合，产出一份 JSON 文件。v5 对每个单元做「34 省 `province_id` 确定性完备切分」，并过**四道闸门**，任一不过即判定未完成、不产出达标文件：

| 闸门 | 含义 |
| --- | --- |
| `G1_base` | 基准 `num_found` 稳定；若被接口截断（上限 10000），则以 34 省分片之和为真值 |
| `G2_partition` | 34 个 `province_id` 分片探测零失败、无封顶分片、分片 Σ 守恒 |
| `G3_pages_zero_fail` | 全部分页请求零失败 |
| `G4_count_match` | 去重后条数 `count` 与守恒基准 `num_found` 精确相等 |

**达标判据**（存档文件中 `gate_pass = true`）：`version = v5`、四道闸门全 `true`、`pages_failed = 0`、`count = num_found = len(items)`。

## 四、文件结构（`原始数据/cutoff_<省>_<年>.json`）

顶层为对象：

| 键 | 含义 |
| --- | --- |
| `version` / `collector_rev` / `build_id` | 采集器版本 / 修订号 / 构建号 |
| `prov` / `year` / `api` | 该文件的考生省份代码 / 年份 / 接口 uri |
| `num_found` / `count` | 守恒基准总条数 / 去重后落库条数（达标时二者相等） |
| `gate_pass` / `gate` | 是否达标 / 四道闸门明细 |
| `pages_total` / `pages_ok` / `pages_failed` | 分页总数 / 成功 / 失败（达标时失败恒为 0） |
| `partition_count` / `base_capped` / `dup_in_api` | 34 省分片条数之和 / 基准是否被截断 / 接口内完全重复记录数 |
| `coverage_pct` / `elapsed` / `collected_at` | 覆盖率 / 采集耗时（秒）/ 采集完成时间 |
| `partition` / `stats` / `query_rounds` / `probe_rounds` / `page_rounds` | 采集过程的分片与重试明细（排障用） |
| `items` | 明细记录数组 |

## 五、明细记录字段字典

`items[]` 每条 37 个字段。源站返回值**几乎全为字符串或数值**，`-` 与空串表示无数据；做数值计算前需统一转型并处理 `-` / 空串。

> 以下含义依据字段名与实测样例推断；标注「原样保留」的是源站编码字段，其枚举字典未考证，按原值存档、**不做清洗或派生**（源站普遍存在布尔用 `1`/`2`、枚举数字编码 + `*_name` 冗余派生、同名跨文件不一致等问题）。

| 字段 | 样例 | 说明 |
| --- | --- | --- |

| `min_section` | `272` | 投档最低分对应位次 |
| `diff` | `284` | 与批次线分差（本例 `min 684 − proscore 400 = 284`） |
| `proscore` | `400` | 批次线（省控线） |

| `avg_section` | `-` | 平均分位次 |
| `filing` | `684` | 源站投档分字段，原样保留（常与 `min` 一致） |
| `major_score` | `-` | 专业分 |
| `num` | `-` | 计划 / 录取人数（多数为空） |
| `admissions` | `1` | 源站字段，原样保留 |

## 六、数据边界提醒
