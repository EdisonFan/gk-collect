# 专业录取线 · 数据说明

## 一、是什么数据

「专业录取线」记录**某高校某个具体专业（含专业方向/班型）在某考生省份、某录取年份、某批次/科类下的录取最低分、最低位次，以及与批次线的分差**等。

一条记录 = 一所院校 × 一个专业 × 一个招生单元。它比同目录的「院校投档线」**粒度更细**：投档线是「院校级」录取门槛，专业录取线是「院校 + 专业」级。同一所院校同一批次下，不同专业的最低分差距很大（专业分差中位数约 59 分），志愿填报时专业线才是真正的比较基准。

## 二、来源接口

| 项 | 值 |
| --- | --- |
| 接口 uri | `apidata/api/gk/score/special` |
| 完整调用 | `POST https://api.zjzw.cn/web/api/`，body 为 `{"uri":"apidata/api/gk/score/special","local_province_id":<省>,"year":<年>,"page":<页>,"size":<每页>}` |
| 查询维度 | `local_province_id`（**考生省份**）× `year`（年份）；`local_province_id` 有效取值 **31 个**（大陆 31 个省级行政区，实测 71 台湾 / 81 香港 / 82 澳门 `numFound=0`） |
| 采集器 | `collect_special.py`，版本 **special-v1.1** |
| 执行环境 | GitHub Actions（`EdisonFan/gk-collect`），每个采集单元一个 `special-<省>-<年>` 分支 |

### 接口的四个硬约束（实测，与投档线不同）

| 约束 | 实测结论 | 采集器的应对 |
| --- | --- | --- |
| **`numFound` 封顶 10000** | 无筛选查询恒为 10000（投档线亦然） | 守恒基准一律改用「34 省分片 Σ」，不拿 BASE 当真值 |
| **`size` 上限 20** | `size=50` 返回空数组 | 固定 `size=20` 起步，按需降级 |
| **翻页上限 200 页（硬编码，与 size 无关）** | `page=201` 起返回空，`size=10` 时同样是第 201 页空 | 单片容量 = `200 × size`：size=20 → 4000 条，size=10 → 2000 条。片容量不足时必须继续切分 |
| **响应体 30000 字符上限** | 字段多时 `size=20` 的响应超长，接口返回 `code=1090`「(api)数据长度超过30000个字符」且**不给 numFound** | v1.1 起按 `size` 阶梯 20→10→5 自适应降级，见下节 |

> `numFound` 与 `size` 无关（实测 p44 片 size=10/5 同为 1328；p41 片 size=10/20 同为 7837），因此降 `size` 只影响响应体长度，**不影响守恒基准的正确性**。

## 三、采集单元与零丢失校验

一个**采集单元** = 一个 `(local_province_id, year)` 组合，产出一份 JSON 文件。采集器对每个单元做「34 个 `province_id` 确定性完备切分」，并过**四道闸门**，任一不过即判定未完成、不产出达标文件：

| 闸门 | 含义 |
| --- | --- |
| `G1_base` | 基准 `num_found` 取到；因本接口 BASE 恒被截断在 10000，一律以 34 省分片之和为真值 |
| `G2_partition` | 34 个 `province_id` 分片探测零失败、无封顶分片、分片 Σ 守恒 |
| `G3_pages_zero_fail` | 全部分页请求零失败 |
| `G4_count_match` | 页任务原始条数与守恒基准 `num_found` 精确相等 |

**达标判据**（存档文件中 `gate_pass = true`）：`version = special-v1.1`、四道闸门全 `true`、`pages_failed = 0`、`count = num_found = len(items)`。

### 分片与切分规则

- **完备切分**：34 个 `province_id`（院校所在省，含港澳台）是确定性完备划分。实测 54-2021 的 BASE=357 与 34 省 Σ=357 精确相等。
- **超限片再切分**：单片 > `200 × size` 时不可采，按 **批次优先 → 科类兜底** 两级切分。顺序不能反——实测 41-2025 的 p41 片（7837 条）按**科类**切 Σ=7817 **不守恒**（漏 20 条艺术类），按**批次**切 Σ=7837 **守恒**；其中「本科批」(4004) 再按科类切 2969+1035=4004 仍守恒。
- **`size` 自适应（v1.1）**：某分片响应体超长返回 `code=1090` 时，该片 `size` 沿 20→10→5 阶梯下降；若采集中途才撞 1090，则**该片整片降 size 重采**（`size` 与页码绑定，改 `size` 会让页内容错位，不能只补失败页）。降 size 后若所需页数超过 200 页上限，该片判失败并要求更细切分。

## 四、文件结构（`原始数据/special_<省>_<年>.json`）

顶层为对象：

| 键 | 含义 |
| --- | --- |
| `version` / `collector_rev` / `build_id` | 采集器版本 / 修订号 / 构建号 |
| `prov` / `year` / `api` | 该文件的考生省份代码 / 年份 / 接口 uri |
| `num_found` / `count` | 守恒基准总条数 / 落库条数（达标时二者相等） |
| `true_num_found` / `base_num_found` / `base_capped` | 34 省 Σ 真值 / 接口原始 BASE 值（恒为假数）/ BASE 是否被截断 |
| `gate_pass` / `gate` | 是否达标 / 四道闸门明细 |
| `pages_total` / `pages_ok` / `pages_failed` | 分页总数 / 成功 / 失败（达标时失败恒为 0） |
| `partition_count` / `dup_in_api` | 页任务原始条数 / 接口内完全重复记录数 |
| `coverage_pct` / `elapsed` / `collected_at` | 覆盖率 / 采集耗时（秒）/ 采集完成时间 |
| `partition` / `stats` | 采集过程明细（排障用）。`partition.provinces` 为各省片条数、`partition.prov_sizes` 为各省片实际使用的 `size`、`partition.splits` 为再切分记录；`stats.oversize` 为撞 `1090` 的次数 |
| `items` | 明细记录数组 |

## 五、明细记录字段字典

`items[]` 每条 **40 个** 个字段（与投档线字段数相同，但内容构成不同：21 个共有 + 19 个专业特有）。源站返回值**几乎全为字符串或数值**，`-` 与空串表示无数据；做数值计算前需统一转型并处理 `-` / 空串。

> 含义依据字段名与实测样例推断；标注「原样保留」的是源站编码字段，其枚举字典未考证，按原值存档、**不做清洗或派生**。

## 六、与院校投档线的关系

| 对比项 | 院校投档线 | 专业录取线 |
| --- | --- | --- |
| 接口 uri | `apidata/api/gk/score/province` | `apidata/api/gk/score/special` |
| 记录粒度 | 院校 × 招生单元 | 院校 × **专业** × 招生单元 |
| 每条字段数 | 40 | 40（构成不同） |
| 切分顺序 | 科类优先 → 批次兜底 | **批次优先 → 科类兜底**（按科类切不守恒） |
| `size` 上限 | 20 | 20（且受响应体 30000 字符上限约束，需自适应降级） |
| 采集器版本 | `v5` | `special-v1.1` |

两者可通过 `school_id` + `local_province_id` + `year` 关联，用于「投档线看院校门槛、专业线看具体专业位次」的交叉分析。

## 七、数据边界提醒

- 本文件只说明「数据是什么」。采集范围、起止边界、复采约定见 [`采集范围.md`](采集范围.md)，条数与达标统计见 [`采集统计.md`](采集统计.md)。
- 本归档是**原始记录**，未做单位换算、枚举翻译、去重以外的清洗；下游使用前请按字段表自行处理 `-`、空串与字符串数值。
- 源站对同一「院校 + 专业」可能存在内容完全相同的重复记录，`dup_in_api` 字段记录了这类重复条数（零丢失校验按接口原始条数守恒，不按去重后条数）。
